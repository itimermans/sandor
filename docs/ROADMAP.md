- The scaffolded example server route is `/sandor/hello` (defined in `sandor/routes.py`), not the
  `/sandor/get-example` name used in some template docs.

### 2026-08-18 — M0 closed: live reload verified, everything commented, VS Code tasks

**M0 is done.** The owner ran the acceptance test — changed the console string in `src/index.ts`,
waited for `jlpm watch`, pressed F5, saw the new string. The whole three-process loop works.

Then, at the owner's request, a documentation-and-ergonomics pass rather than new features:

- **Every source file now carries a header comment explaining what it is and why** (D16) — both
  TypeScript files, all Python, the styles, and the JS build configs. These are written for someone
  fluent in C/C++/Python and new to the web stack, so they explain Promises, `===` vs `==`, the
  CommonJS/ESM split, module federation, and so on where those first appear.
- **`WORKFLOW.md` §11 is a new repository map.** It exists specifically for the files that *cannot*
  carry comments because a strict JSON parser reads them — `package.json`, `schema/plugin.json`,
  `install.json`, `jupyter-config/server-config/sandor.json`. Those four are explained in full there
  and nowhere else.
- **`.vscode/` is committed**: `tasks.json` (Ctrl+Shift+B starts watch + lab side by side;
  `Sandor: stop` kills them), `settings.json`, `extensions.json`.
- **`tools/stop_dev.py`** backs the stop task.

**Learned / surprises:**

- **`tsconfig.json` and everything under `.vscode/` are JSONC** — comments are legal and the
  toolchain accepts them. `package.json`, `schema/plugin.json`, and `install.json` are **not**; a
  comment there is a hard syntax error. That asymmetry is the whole reason the repository map exists.
- **A "stop everything" script is dangerous in a way that is easy to miss.** VS Code is an *ancestor
  process* of any task it runs, it is an Electron app so its process name matches `node`, and its
  working directory is very likely the repo root. A naive "kill anything node-ish rooted in this
  repo" sweep closes the editor. `tools/stop_dev.py` walks `psutil.Process().parents()` and excludes
  the entire ancestor chain. Do not remove that guard.
- **Prettier was reformatting `docs/*.md`**, reflowing the tables in DESIGN.md into unreviewable
  diffs. `*.md` is now in `.prettierignore`, and `.vscode/settings.json` disables format-on-save for
  markdown to match. `uv run jlpm lint:check` is clean.
- **`jlpm test` prints `jest-haste-map: Haste module naming collision` warnings.** Harmless: jest
  walks the tree and finds several `package.json` files sharing a `name` — ours, the built copy in
  `sandor/labextension/`, and JupyterLab's own `staging`/`static` inside `.venv`. Suite passes.
  Logged in the troubleshooting table so nobody chases it again.
- **`psutil` was added to `[dependency-groups] dev` only** — deliberately not a runtime dependency
  and not in the pip extras, because D6 means nothing a *user* runs may depend on it.
- The M0 acceptance-test edit had temporarily broken the Galata UI test, which asserts on the exact
  activation string. The string is restored and now lives in an `ACTIVATION_MESSAGE` constant with a
  comment at both ends of the duplication. It cannot be deduplicated: the UI test runs against the
  *built and installed* extension and cannot import from `src/`.

`uv run jlpm build:lib` (clean) · `uv run jlpm lint:check` (clean) · `tools/stop_dev.py` (found and
